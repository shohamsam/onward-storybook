Header "Archive" (same type as "Your stack", no count), a full-width filter, a flat list of `ArchiveRow`s, the Bottom Nav with Archive current. **Filter** (decision 3): the existing SegmentedControl, four options labelled `All · 37` / `Rejected · 25` / `Ghosted · 8` / `Other · 4` (a middle dot, counts computed from `records`), segments 44px tall, on a white track (decision 4, via the control's new `--segment-track-bg` hook). `Other` is every reason that is not exactly `Rejected` or `Ghosted`. Hidden when there are no records. Changing the filter closes the open row. The filter is `scrollable` (Shoham, 2026-10-19, after seeing it on her iPhone): every segment is padded 12px each side and sized to its content, so the title and count are never cut, and the track scrolls sideways when the four don't fit (at 393px wide, with the brief's counts, they just don't). The selected segment is scrolled fully into view. This replaced a shrink-and-ellipsis version made after QA at 320px. **Opening** (decision 6): tapping a row replaces it, in place, with the full Card in archived mode (see Card's `onRestore`), so any other open row closes; Show less puts the row back. The page scrolls; nothing is clipped. Focus moves to the opened card and returns to the row on close. After Restore, focus goes to the next row's button (else the previous one, else the filter, else the header) once the parent has removed the record. No animation, so there is nothing to gate for reduced motion. **Empty** (decision 10): `Nothing archived yet` with no button and no filter; a filter that matches nothing shows the same block headed `Nothing here` (same body line — a literal reading of "the same empty block"; reversible).
